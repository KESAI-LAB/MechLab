# MechLab · 使用说明

## 一、打开

双击桌面的 **`MechLab`**（快捷方式），或直接双击仓库里的
`scripts/启动MechLab.bat`。

窗口分三块：上方填写参数，中间按钮，下方日志。

## 二、填写顺序

| 步骤 | 填什么 | 说明 |
|---|---|---|
| ① 模型文件 | 点“浏览…”选 `.mph` | 模型里 `std1` 的时间点决定输出时刻 |
| ② 提交到 | `K 本机` / `A 机` / `E 机` | 切换机器时核数会自动改默认值 |
| ③ 核数 | 整数 | K=8、A=30、E=22 是默认，可改（勿超过机器物理核数）|
| 研究步 | 默认 `std1` | 一般不用改 |
| 输出标签 | 任意短名 | 决定 CSV 文件名后缀 |
| ④ 探针 | `label=表达式@域` | 多项用 `;` 分隔 |

## 三、探针写法

```
SiC_hoop=solid.sphi@2          ← SiC 域（域 2）环向应力
SiCin_hoop=solid.sphi@b13,18   ← SiC 内表面（边界 13、18）
IPyC_hoop=solid.sphi@4,5       ← IPyC 上下半球
band_d=phi@6                   ← 赤道带损伤
Int_d=phi@3                    ← 界面层损伤
```

- **域**：直接写数字，多个用逗号：`@2`、`@4,5`
- **边界**：加 `b` 前缀：`@b13,18`（**仅 K、A 机支持**）
- 表达式可以是任意 COMSOL 表达式，例如 `solid.sphi*0.5`、`phi+1`

## 三·五、测试连接

点 **🔌 测试连接**，几秒出结果，日志里看两行：

| 输出 | 含义 |
|---|---|
| `LINK_OK` | ssh 连上了（K 机没有这行）|
| `COMSOL_OK` | 远程/本机 COMSOL 求解器存在 |
| `COMSOL_MISSING` | 机器通但 COMSOL 路径不对 |

建议每次换机器先点一次。

## 三·六、多个研究步的顺序

“研究步”栏：

| 写法 | 行为 |
|---|---|
| `std1` | 只跑 std1 |
| `std1,std2` | **先 std1，再 std2**（std2 在 std1 的结果模型上继续，输出逐级链式传递）|
| 留空 | 按模型顺序跑全部研究步 |

## 三·六五、文件夹批量 + 两步提交

1. 左侧「模型文件夹」→ 选目录 → 列出所有 `.mph`
2. 选若干（Ctrl/Shift 多选）→ **加入选中**，或 **全部加入**
3. 此时任务是 **待提交**（灰色），**机器不会开算**
4. 确认参数后：**▶ 提交选中** / **▶▶ 提交全部**
5. 左侧可随时「刷新」重新读文件夹

## 三·六六、保存全部解

勾选顶部 **“保存全部解”** 再加入队列；任务表「存解」列显示是否勾选。
求解完成后解模型会留在：

| 机器 | 路径 |
|---|---|
| K 本机 | `<模型目录>/solved/` |
| A 机 | `<RG_BASE_WIN>\solutions\` |
| E 机 | `<RG_BASE_WIN>\store\`（或自定义 `SAVE_DIR_WIN`）|

不勾选时保持零残留（解得完就删）。

## 三·七、多机器排队与中止

**每台机器一条队列**，可以同时把不同模型丢给不同机器：

1. 选模型 → 选机器 → 点 **＋ 加入队列**（可以连续加多个）
2. 同一个机器的任务会**排队串行**；不同机器**并行**
3. 机器状态条显示：`运行 <id>（N s） · 排队 M`
4. 表格里选中一行 → 下方显示该任务的实时日志
5. **■ 中止选中**：杀掉本地进程树，并清理该机器上的 `comsolbatch`
6. 任务列表会存盘（`app/jobs.json`），关掉重开还在

## 三·八、进度列

| 显示 | 含义 |
|---|---|
| `研究 1/2 · t≈453 d` | 正在跑第 1 个研究步，物理时间约 453 天 |
| `日志 25 s 前更新` | 还没解析到时间步（刚启动），但进程在写日志 |
| 整行**黄色 ⚠ 可能卡住** | 日志 10 分钟没有增长，建议去看机器或中止 |

解析不到 COMSOL 内部格式时只显示日志新鲜度，不会给出错误百分比。

### 判断“不收敛 / 卡住”的正确姿势

| 现象 | 含义 | 做法 |
|---|---|---|
| 进度列 `t≈…` 正常增长 | 在算 | 等 |
| 整行黄色 `⚠ 可能卡住` | 10 分钟没写日志 | 看机器或中止 |
| 进度列出现 `NLfail=N` 且 N 变大 | 非线性迭代失败增多 | 可能要改时间步/初值 |
| 精简视图“最近时间步”里 Res 持续上升 | 迭代发散前兆 | 中止，调整后重跑 |
| 日志出现 `不收敛` / `Error` | 已失败 | 中止，看完整日志 |

### 日志面板

- 默认**精简视图**（只留关键信息 + 最近时间步）
- 勾选 **完整日志** 看全部
- **收起日志 ▴** 把日志整块折叠

## 四、提交与结果

点 **▶ 提交计算** 后：

1. 先看日志窗口，出现 `求解中 ...` 表示已开始
2. 状态栏显示 `运行中… N s`
3. 完成时显示 `完成 ✓`，同时 CSV 写在**模型所在目录**：

```
<模型名>_<标签>_ts.csv
列：t_d, <label>_min, <label>_max, <label>_mean
```

4. 点“打开模型目录”可以直接定位到 CSV

## 五、注意事项

| 事项 | 说明 |
|---|---|
| **一台机器同时只跑一个** | GUI 不排队；A、E 机是独占，重复提交会互相拖慢/冲突 |
| **E 机不支持边界探针** | 选 E 机时界面会自动换成纯域探针；要用 `@b…` 请选 K 或 A |
| **关窗口会中断** | 本地 K 机的求解进程会结束；A/E 机的远程任务可能仍在跑，需要去机器上确认 |
| **长任务** | 1000 天、27 万单元的模型大约：A 机 25–35 min，E 机 55–60 min，K 机视本机性能而定 |
| **磁盘** | K 机在模型目录下建 `.runs/` 临时目录，成功后自动删除 |

## 六、常见问题

**Q：日志里只有 `[GUI] 命令：…` 然后没动静？**
A：可能 ssh 连不上（A/E 机）。先在命令行手动试一次：
`ssh <A_USER@A_HOST> echo ok`（A）或 `ssh <E_USER@E_HOST> echo ok`（E）。

**Q：E 机连接超时？**
A：检查 `engine/remote/env_evior.sh` 里的 `RG_HOST`（可参考 `env_evior.example.sh`），确保地址/端口/私钥正确。

**Q：想加一台机器 / 加一个探针预设 / 加时间点控制？**
A：见 `README.md` 的“加一台机器 / 加功能”一节；改 `app/config.py` 和 `app/backends.py` 即可。
